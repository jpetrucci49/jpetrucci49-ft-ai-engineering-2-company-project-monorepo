## 2. Layout

```text
uis/backoffice/
  app/(authenticated)/inventory/
    products/page.tsx
    orders/page.tsx
    orders/inbound/page.tsx
    orders/outbound/page.tsx
  app/api/inventory/
    products/route.ts              GET
    products/[id]/route.ts         GET
    orders/route.ts                GET
    orders/inbound/route.ts        POST
    orders/outbound/route.ts       POST
  components/inventory/            ← client pages/forms (thin route files)
  lib/api/inventory.ts             ← only browser module that calls fetch (via authFetch)
  lib/api/inventory-server.ts      ← BFF proxy to FastAPI /inventory
  types/inventory.ts               ← types matching API JSON
```

Browser → same-origin `/api/inventory/*` → FastAPI `/inventory/*`. Do not call `:8000` from the client. Forward `Authorization`. Use `runBffHandler` + `proxySanitizedResponse`.

Env: `INVENTORY_API_URL` (default `http://127.0.0.1:8000`) in `.env.example`.

Auth: pages live under `(authenticated)` — no extra guard. Add nav in `BackofficeShell`: **Supplies** → `/inventory/products`, **Movements** → `/inventory/orders`.

Hooks only. Reuse `LoadingState` / `ErrorState` (retry). `npm run lint` and `npm run build` in `uis/backoffice/`. Verify in the browser (catalogue, both forms, movements, logged-out redirect).

## 3. Client API — `lib/api/inventory.ts`

No component `fetch`. Use `authFetch` (token in `localStorage`). On `!ok`, parse `detail` (string or M12 validation array) and throw a typed error with `status` + message. Never swallow. Map 5xx via `toUserFacingMessage`; keep **400 insufficient-stock** text as-is (exact API sentence).

| Helper | FastAPI |
| --- | --- |
| `listSupplies()` | `GET /inventory/products` |
| `getSupply(id)` | `GET /inventory/products/{id}` |
| `createDelivery(body)` | `POST /inventory/orders/inbound` |
| `createConsumption(body)` | `POST /inventory/orders/outbound` |
| `listMovements()` | `GET /inventory/orders` |

## 4. Pages

### `/inventory/products` — catalogue

`GET` list. Columns: name, SKU, category, unit, jurisdiction, **current stock**.

Stock indicators (network-wide; not per clinic) — put this comment next to the helper:

```ts
// Out of stock: 0 (red). Low: 1–10 (amber) — restock before the next clinic shift.
// Healthy: > 10 (green). Thresholds are UX-only; the API still enforces non-negative stock.
```

Each row: **Log vendor delivery** and **Log clinical consumption** → the matching form with `?supply_id={id}`.

Empty: short “No medical supplies in the catalogue.” + retry on load error.

### `/inventory/orders/inbound` — vendor delivery

Fields: supply (select by **name**, value = id), quantity (> 0), vendor, clinic (labelled 1–12). Prefill supply from `?supply_id=`.

POST body: `supply_id`, `quantity`, `vendor_name`, `clinic_id`. On **201**: reset fields (keep `supply_id` if it came from the query), `role="status"` confirmation. On error: visible `role="alert"` with API message.

### `/inventory/orders/outbound` — clinical consumption

Fields: supply select, **current stock** (read-only, updates when selection changes via `getSupply`), quantity, consumption type (clinical use / expiry waste), clinic. Prefill `?supply_id=`.

If quantity > displayed stock, show a **warning** near quantity (do not block submit). On API **400** insufficient stock, show that message **inline next to quantity**. Other errors: page-level alert. On **201**: clear quantity (and type if you like), confirmation, refresh displayed stock.

### `/inventory/orders` — movements (read-only)

`GET` list. Columns: supply name, SKU, quantity, type, clinic, recorded at, logged by. Distinguish delivery vs consumption (colour + label). No edit/delete.

- [ ] Unauthenticated visit to any of the four routes → login
- [ ] Catalogue shows seeded supplies and computed `current_stock` with 0 / low / healthy styling
- [ ] Row links open the correct form with that supply selected
- [ ] Delivery form: name selector, success clears + confirms, 4xx/5xx message on screen
- [ ] Consumption form: stock refreshes on supply change; oversell warning; API 400 on quantity field
- [ ] Movements lists both types with name, qty, type, date, `user_uuid`
- [ ] No raw `fetch` in components; no `NEXT_PUBLIC_` FastAPI URL
