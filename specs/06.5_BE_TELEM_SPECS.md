Capture is done. This milestone **replaces the stub** with a write-only store. One HTTP batch → **one database transaction**.

## 1. Constraints (read first)

### 1.1 Why bulk insert

The backoffice flushes up to **20 events / 10s**, many users in parallel. One INSERT per event ⇒ one transaction per event ⇒ connection-pool collapse. Valid rows in a batch go in **one** `add_all` / `insert` and **one** commit (the existing `get_db()` commit is enough — do not `commit()` inside the per-event loop).

### 1.2 Partial acceptance

**Forbidden:** `events: list[TelemetryEvent]` on the request body. FastAPI/Pydantic would 422 the whole batch if one item is bad; the frontend retries or drops everything.

**Required:**

1. Body type is a **loose** envelope: `{ "events": [ ... ] }` where each item is `dict` / `Any`, not `TelemetryEvent`.
2. In the handler, `TelemetryEvent.model_validate(raw)` per item inside `try/except ValidationError`.
3. Valid → bulk list. Invalid → `rejected += 1`. Loop continues.
4. HTTP **200** whenever `events` is a JSON array. Return `{ "received", "stored", "rejected" }`.
5. Missing/non-array `events` → existing 400 sanitised validation (envelope unparseable).

The frontend only checks `response.ok`. Extra keys (`stored`, `rejected`) are compatible. Keep `received`.

### 1.3 Privacy

Never persist PHI or credentials in `tags` / `message`. Drop keys `email`, `password`, `token`, `authorization`, `description` if present. `userId` in tags is the **staff** id string or JSON `null`. `department` is a clinical area, never a person.

### 1.4 Out of scope

- Frontend queue/instrumentation changes
- Query/report endpoints (next project)
- Alembic (same learning rule as inventory: `create_all` locally; document that production would migrate)
- `uis/website/`, talent tracker

## 2. Phase 1 — table

### 2.1 Files

```text
services/api/telemetry/
  models.py       # TelemetryEvent UNCHANGED; replace TelemetryBatchIn/Out only
  table.py        # SQLModel table telemetry_events
  mapping.py      # TelemetryEvent → row (level, value, message, tags)
  repository.py   # bulk_insert(session, rows) — one shot, no per-row commit
  schema.sql      # identical DDL for Supabase SQL Editor
  router.py       # replace stub
```

Reuse `inventory.database.get_engine` / `get_db`. **One pool.** Import `telemetry.table` from `init_inventory_schema()` (or rename that helper to `init_sql_schema`) so `create_all` includes the new table.

### 2.2 Columns

| Column | Type | Notes |
| --- | --- | --- |
| `id` | UUID PK | Postgres: `gen_random_uuid()`. SQLite/tests: `default_factory=uuid4` |
| `timestamp` | timestamptz NOT NULL | from envelope |
| `service` | text NOT NULL | `"backoffice"` (emitter is the UI) |
| `event_type` | text NOT NULL | envelope `event_type` |
| `level` | text NOT NULL default `info` | `info` \| `warn` \| `error` only |
| `value` | numeric NULL | see mapping |
| `message` | text NULL | short, no PII |
| `tags` | jsonb default `{}` | properties + correlation keys |

CheckConstraint on `level`. No `onupdate`. No unique on `eventId` this phase (store it in `tags`).

**Indexes:** `timestamp`, `event_type`, GIN on `tags` (`postgresql_using="gin"`). SQLite: skip GIN (dialect-specific; `create_all` must still succeed in tests).

### 2.3 Row mapping (`mapping.py`)

| DB | Source |
| --- | --- |
| `timestamp` | `event.timestamp` |
| `service` | `"backoffice"` |
| `event_type` | `event.event_type` |
| `level` | table below |
| `value` | first defined numeric among `properties.value`, `properties.duration_ms`, `properties.quantity` |
| `message` | optional one-line: `event_type` plus `product_id` or `route` if present — **never** error text or emails |
| `tags` | allowlisted `properties` **plus** correlation keys |

**`level`**

| `event_type` | `level` |
| --- | --- |
| `frontend_error_uncaught` | `error` |
| `login_failed`, `session_expired`, `outbound_order_rejected`, `inventory_validation_failed`, `direct_stock_edit_rejected`, `stock_threshold_triggered`, `supply_expiry_flagged` | `warn` |
| everything else | `info` |

**`tags` (document this in `docs/telemetry/telemetry-plan.md` — new short § “Storage mapping”)**

```text
tags = {
  ...allowlisted properties...,
  "eventId": event.eventId,
  "sessionId": event.sessionId,
  "userId": event.userId,          # string or null
  "schemaVersion": event.schemaVersion,
  "requestId": event.requestId,
}
```

Strip unknown property keys the same way the frontend allowlist does (copy key sets from `uis/backoffice/lib/telemetry/allowlist.ts` / `event-schemas.json`). Correlation keys are **in addition to** properties, not instead.

JSONB: Postgres `JSONB`, SQLite `JSON` variant so tests pass.

### 2.4 `schema.sql`

Idempotent `CREATE TABLE IF NOT EXISTS telemetry_events (...)` plus the three indexes (`IF NOT EXISTS`). Match SQLModel. Used only if dashboard create is needed.

## 3. Phase 2 — real `POST /telemetry/events`

Still **unauthenticated** (`sendBeacon` cannot send `Authorization`). CORS unchanged.

### 3.1 Models (`models.py`)

Keep `TelemetryEvent` as-is.

```python
class TelemetryBatchEnvelope(BaseModel):
    events: list[Any]  # raw dicts; NOT list[TelemetryEvent]

class TelemetryBatchOut(BaseModel):
    received: int
    stored: int
    rejected: int
```

Remove or stop using `TelemetryBatchIn` with `list[TelemetryEvent]`.

### 3.2 Handler

```text
received = len(batch.events)
rows = []
rejected = 0
for raw in batch.events:
    try:
        event = TelemetryEvent.model_validate(raw)
        rows.append(to_row(event))
    except ValidationError:
        rejected += 1
if rows:
    bulk_insert(session, rows)   # add_all / insert; no commit in the loop
return { received, stored: len(rows), rejected }
```

Empty `events` → `{ received: 0, stored: 0, rejected: 0 }` still 200.

Log **counts + stored `event_type`s only**, not `tags`.

No GET/PATCH/PUT/DELETE for telemetry rows.

### 3.3 Tests (`services/api/tests/test_telemetry.py`)

Use the existing in-memory SQLite `inventory_client` (same engine after `create_all`).

| Case | Expect |
| --- | --- |
| Two valid events | 200 `{ received: 2, stored: 2, rejected: 0 }`; two rows |
| One valid + one missing `eventId` | 200 `{ received: 2, stored: 1, rejected: 1 }` — **not** 400/422 |
| Empty `events` | 200 all zeros |
| Body without `events` | 400 |
| All invalid | 200 `stored: 0`, `rejected: N`, table unchanged |
| Query DB | `event_type`, `timestamp`, `tags` contain `eventId` and allowlisted keys; no `email` |

Delete the old assertion that a missing `eventId` in a well-shaped `{ events: [...] }` returns **400**.
