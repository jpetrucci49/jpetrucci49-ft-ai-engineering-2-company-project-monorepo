# SPECS — Milestone 6.5: Backoffice telemetry capture

Design is approved. This milestone **captures** events in the backoffice and ships them to a **temporary FastAPI stub**. No database writes.

**Do not write instrumentation before the service exists.** Order is mandatory: **stub → service → instrumentation**.

| Source | Role |
| --- | --- |

## 0. Constraints (read first)

### 0.1 Single public API

All backoffice tracking goes through:

```ts
track(eventType: string, properties: Record<string, unknown>): void
```

`eventType` becomes envelope `event_type`. Components never call `fetch` / `axios` / `sendBeacon` for telemetry. Only `TelemetryService` talks to the endpoint.

### 0.2 Privacy — never emit

| Forbidden | Why |
| --- | --- |
| Patient name, MRN, diagnosis, clinical free text | PHI (HIPAA / UK GDPR) |
| Login email, password, reset token, JWT | Credentials / PII |
| Client IP, user-agent (as event properties) | Unnecessary personal data |
| Incident `description` | Can contain PHI |
| Supplier `monthly_rate` amount | Commercial |
| Full 400 request bodies / Pydantic `input` | M12 leak |

`userId` is the **staff** TinyDB id as a string (JWT `sub`). Never an email. `department` is a clinical **area** enum, never a person.

Stub logs: **count + `event_type` list only**. Do not log `properties` or envelope ids that are unnecessary.

### 0.3 Out of scope

- Persistence / Supabase (next phase)
- `uis/website/`, `uis/talent-pipeline-tracker/`
- Changing CONTEXT or milestone files
- Inventing expiry dates or patient-shaped test data

## 1. Phase 1 — FastAPI stub

Temporary verification only. Phase 3 will replace the handler; keep `TelemetryEvent` reusable.

### 1.1 Files


### 1.2 Models (`TelemetryEvent`)

Match the approved envelope **exactly** (mixed camelCase / snake_case is intentional):

| Field | Type | Notes |
| --- | --- | --- |
| `eventId` | `str` | UUID |
| `timestamp` | `datetime` | ISO 8601 |
| `sessionId` | `str` | |
| `userId` | `str \| None` | `null` on failed login / unknown actor |
| `event_type` | `str` | |
| `schemaVersion` | `str` | |
| `requestId` | `str` | UUID |
| `properties` | `dict[str, Any]` | default `{}` |

```python
class TelemetryBatchIn(BaseModel):
    events: list[TelemetryEvent]

class TelemetryBatchOut(BaseModel):
    received: int
```

Validate **envelope shape only**. Do not persist. Do not enforce per-event allowlists here.

### 1.3 `POST /telemetry/events`

- Body: `{ "events": [ ... ] }`
- Auth: **none** (`sendBeacon` cannot attach `Authorization`)
- CORS: already enabled; browser origin is `:3001`
- On success: `200` `{ "received": N }` (`N = len(events)`; empty list → `0`)
- Log: `received=N types=inbound_order_created,page_viewed,...`
- Invalid envelope → existing 400 sanitised validation handler

### 1.4 `TELEMETRY_ENDPOINT`

Read in `telemetry/config.py` (empty string allowed). Log the value at import/startup. **Do not proxy or redirect** this phase — establish the env pattern only.

Document in `services/api/.env.example` and root `.env.example`:

```text
TELEMETRY_ENDPOINT=http://localhost:8000/telemetry/events
```

### 1.5 Tests

`services/api/tests/test_telemetry.py`:

- Valid batch of 2 events → 200 `{ "received": 2 }`
- Missing `eventId` → 400
- Empty `events` → 200 `{ "received": 0 }`

Do not assert on log text.

## 2. Phase 2 — `TelemetryService` (backoffice)

This app has no `src/` folder. Use `uis/backoffice/lib/telemetry/` (equivalent to the programme’s `src/services/telemetry.ts`).

Do **not** start Phase 3 until `track()` queues and flushes.

### 2.1 Files

```text
uis/backoffice/lib/telemetry/
  constants.ts     # SCHEMA_VERSION = "1.0.0", FLUSH_INTERVAL_MS = 10_000, MAX_QUEUE = 20, MAX_RETRIES = 3
  types.ts         # TelemetryEvent, envelope types
  allowlist.ts     # per-event property keys from event-schemas.json
  mapInventory.ts  # clinic→country, API category→telemetry product_category
  service.ts       # queue, flush, track, setTelemetryUser
  init.ts          # timers, beacon, error + vitals listeners
```

Client-only. Import from a small client provider (see §2.6), never from a Server Component.

### 2.2 Env

| Variable | Where | Value |
| --- | --- | --- |
| `NEXT_PUBLIC_TELEMETRY_ENDPOINT` | `uis/backoffice/.env.example` **and** local `.env.local` (do not commit `.env.local`) | `http://localhost:8000/telemetry/events` |
| Same key | root `.env.example` (Compose; browser still uses localhost) | same URL |

If the env var is missing: no-op `track()` in production; `console.warn` in development. Never throw from `track()`.

### 2.3 Envelope — filled by the service, not callers

`track()` accepts **only** `eventType` + `properties`. The service sets:

| Field | Rule |
| --- | --- |
| `eventId` | `crypto.randomUUID()` at capture |
| `timestamp` | `new Date().toISOString()` at capture (not at flush) |
| `sessionId` | UUID in `sessionStorage` key `healthcore_telemetry_session`; create on first `track` / `initTelemetry` |
| `userId` | staff id string from `setTelemetryUser`, or `null` |
| `schemaVersion` | `"1.0.0"` |
| `requestId` | new UUID per event |
| `event_type` | the `eventType` argument |
| `properties` | **allowlist-stripped** copy (drop unknown keys; do not throw) |

`setTelemetryUser(userId: string | null): void` — call after login / `/api/auth/me`, and with `null` on logout or failed login.

### 2.4 Queue, batch, beacon, retry

| Rule | Value |
| --- | --- |
| Queue | in-memory array |
| Flush | every **10s** **or** when length ≥ **20**, whichever first |
| Body | `{ events: TelemetryEvent[] }` `Content-Type: application/json` |
| Success | HTTP 200 → drop the sent batch |
| Failure | retry up to **3** times, exponential backoff (e.g. 500ms × 2^n); then **discard** that batch |
| Hide / close | `visibilitychange` → `document.visibilityState === "hidden"` → `navigator.sendBeacon(url, blob)` |
| Loop | never `track` the telemetry request itself |

`sendBeacon` fallback: `fetch(..., { keepalive: true })` if beacon is unavailable.

Throttle (from the plan; implement in `track` or a thin wrapper, not in pages):

| `event_type` | Rule |
| --- | --- |
| `page_viewed` | once per `route` per `sessionId` |
| `catalogue_viewed` | once per catalogue visit (not per table re-render) |
| `api_latency_recorded` | 10% sample **or** always if `duration_ms >= 500` |
| `frontend_error_uncaught` | dedupe `{route, name, digest}` for 60s |
| `stock_threshold_triggered` | once per `{product_id, threshold_kind}` per 15 min unless quantity band changes |
| `web_vital_recorded` | once per `{name, route}` per session |
| `login_failed` | no throttle |

### 2.5 Public surface

```ts
export function track(eventType: string, properties?: Record<string, unknown>): void;
export function setTelemetryUser(userId: string | null): void;
export function initTelemetry(): void; // idempotent
```

Nothing else is imported by feature code.

### 2.6 Boot

Add `uis/backoffice/components/telemetry/TelemetryProvider.tsx` (`"use client"`). Call `initTelemetry()` in `useEffect`. Mount it from `uis/backoffice/app/layout.tsx` wrapping `{children}`.

## 3. Phase 3 — Instrumentation

Use **only** allowlisted keys. Map inventory fields in `mapInventory.ts`; do not pass API-only category values (`wound_care`, `diagnostics`) as `product_category`.

### 3.1 Shared maps (from the plan)

**`product_category`:** `ppe` → `ppe`; `medications` → `medication`; `consumables` | `wound_care` | `diagnostics` → `consumable`; future equipment → `equipment`.

**`country`:** clinic `1–9` → `US`; `10–12` → `UK`.

**`department` allowlist:** `general_consultation` · `chronic_care` · `specialty_care` · `chronic_disease_management` · `pharmacy`.

**Stock bands:** `LOW_STOCK_MAX = 10` (`types/inventory.ts`). `quantity` on threshold events is **remaining** units. `threshold_kind`: `out` if remaining ≤ 0, else `low`. `threshold_value`: `0` or `10`.

### 3.2 Mandatory (must all fire from the backoffice)

| `event_type` | When | Where to hook | Required `properties` |
| --- | --- | --- | --- |
| `inbound_order_created` | delivery `201` | after `createDelivery` succeeds (`DeliveryForm` or inventory client) | `clinic_id`, `country`, `product_id`, `product_category`, `quantity`, `vendor_name`, `order_id`; optional `sku` |
| `outbound_order_created` | consumption `201` | after `createConsumption` succeeds | `clinic_id`, `country`, `product_id`, `product_category`, `quantity`, `department`, `consumption_type`, `order_id`; optional `remaining_stock` |
| `stock_threshold_triggered` | remaining stock ≤ 10 after a movement (or catalogue row already at/below) | after inbound/outbound success using returned/refetched `current_stock`; optional scan on catalogue load | `clinic_id`, `country`, `product_id`, `product_category`, `quantity` (remaining), `threshold_value`, `threshold_kind`; optional `trigger_order_type` `inbound` \| `outbound` \| `scan` |
| `direct_stock_edit_rejected` | PATCH/PUT/DELETE on a product is rejected | `lib/api/inventory.ts`: any such call to `/api/inventory/products/:id` returning 4xx | required: `http_method`, `http_status`, `route` (`^/inventory/`); optional clinic/product fields if known. **No request body in properties.** |
| `supply_expiry_flagged` | supply has `expiry_date` within 30 days and remaining qty > 0 | after `listSupplies` / `getSupply` via a scanner; once per `product_id` per session | `country`, `product_id`, `product_category`, `quantity`, `expiry_date` (`YYYY-MM-DD`), `days_to_expiry` (0–30); optional `clinic_id`, `department` |

**`department` on outbound:** the API payload has no department today. Add a **department `<select>`** on `ConsumptionForm` (labels only; HealthCore terms). Send it in telemetry only — do not add it to the FastAPI inventory contract this milestone.

**`direct_stock_edit_rejected`:** do **not** add a stock-editor UI. Wire the client so a PATCH/PUT/DELETE is tracked when it happens. Export a test helper e.g. `requestDirectStockEdit(id)` used only from tests or a clearly labelled internal action that expects 404/405. No `quantity` of “set stock” in the body of the event.

**`supply_expiry_flagged`:** `MedicalSupply` has no `expiry_date` yet. Extend the TS type with **optional** `expiry_date?: string`. Implement `flagExpiringSupplies(supplies)`. **Do not fabricate dates** in app code. If the API sends no dates, the hook is still required; cover the scanner with a unit fixture that includes `expiry_date`.

### 3.3 Identified — must cover every category

Prioritise **breadth** (inventory + auth + performance + errors + navigation).

| `event_type` | Category | When | Hook | Required `properties` |
| --- | --- | --- | --- | --- |
| `inventory_validation_failed` | inventory | inventory 400 that is **not** insufficient-stock | inventory client | `route`, `error_code`; optional `field`, clinic/product/qty. Never the raw body |
| `outbound_order_rejected` | inventory | outbound 400 + `isInsufficientStockMessage` | after `createConsumption` fails | `clinic_id`, `country`, `product_id`, `product_category`, `quantity`, `available`, `requested`; optional `department`, `product_name` (supply name only) |
| `catalogue_viewed` | inventory | catalogue data loaded | `SupplyCataloguePage` | `result_count`, `out_of_stock_count`, `low_stock_count` |
| `login_failed` | auth | login 401 / inactive / bad body / network | **`LoginForm` only** (not each page) | `reason`: `invalid_credentials` \| `inactive` \| `malformed` \| `network_error`. `userId` must be `null` |
| `login_succeeded` | auth | login 200 | **`LoginForm`**: after token set, `GET /api/auth/me`, then `setTelemetryUser(String(profile.user_id))` | `role`: `admin` \| `manager` \| `user` |
| `session_expired` | auth | API **401** while a token existed | **`authFetch` or `AuthGuard`** — not per page. Skip first visit with no token | `from_route` (`^/`) |
| `api_latency_recorded` | performance | BFF `authFetch` / inventory `requestJson` | wrap timing in one place (`authFetch` or inventory client) | `route_template`, `method`, `status_code`, `duration_ms`, `layer`: `"bff"` |
| `frontend_error_uncaught` | errors | `window.onerror`, `unhandledrejection`, `error.tsx` | `init.ts` + existing `app/error.tsx` | `route`, `name`; optional `digest`. **No `error.message` if it might contain input** |
| `page_viewed` | navigation | main section changes | `BackofficeShell` or a pathname effect | `route`; optional `referrer_route` |
| `flow_abandoned` | navigation | inbound/outbound form unmount without 201 | `DeliveryForm` / `ConsumptionForm` | `flow`: `inbound_order` \| `outbound_order`; `last_step`; `duration_ms` |
| `web_vital_recorded` | performance | Web Vitals callback | `init.ts` via `web-vitals` | `name` (`CLS`\|`INP`\|`LCP`\|`FCP`\|`TTFB`), `value` (number), `route` |

Add `web_vital_recorded` to `event-schemas.json` (identified · performance · batch) with that allowlist. Do not add other new types.

**`login_failed.reason`:** the programme lists `session_expired` as a login reason — **ignore that**. Session expiry is `session_expired`. Extend the JSON schema with `network_error` only.

**Page views — at least:** `/`, `/inventory/products`, `/inventory/orders`, `/inventory/orders/inbound`, `/inventory/orders/outbound`, `/incidents`, `/suppliers`, `/login`.

### 3.4 Auth hooks (do not scatter)

| Event | File |
| --- | --- |
| `login_failed` / `login_succeeded` | `uis/backoffice/components/auth/LoginForm.tsx` |
| `setTelemetryUser(null)` on logout | `LogoutButton.tsx` |
| `session_expired` | `packages/shared/auth/fetch.ts` on 401 **or** a backoffice wrapper — fire **before** redirect. Do not emit on public `/login` first paint |

Never put the submitted email or password in `properties`.
